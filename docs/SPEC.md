# The maiku descriptor, v0

`schema_version: "maiku/v0"`. Machine-readable schema:
[`schemas/participant-descriptor.schema.json`](../schemas/participant-descriptor.schema.json),
regenerated by `uv run python scripts/emit_schema.py`.

## Identity

`id` is `mk:` plus the first 32 hex characters of a SHA-256 over the canonical JSON of the
descriptor, **excluding `runtime`, `bindings`, `display`, `provenance`, `liveness`, `signature`
and `id` itself**.

Identity is capability: the affordance set, plus the `handle` that addresses it. Everything
about where a participant runs, how it is reached, who made it and what it is called sits
outside — so restarting a model on another port, moving it to another host, renaming it or
attributing it to a vendor all leave the same participant, while adding an affordance or
changing a schema mints a new one.

`handle` stays inside because it is a position rather than a label: two people who both afford
only `approve` are genuinely different participants, and one id for both would be wrong.

A serialized descriptor carries its `id`. Reading one back verifies it, so a load catches any
edit to what the participant can do. Edits to where it is reached fall outside that check by
design; `signing_payload` covers them for anyone who signs.

## Capability id

`capability_id` is `cap:` plus the same hash taken with `handle` excluded as well. `id` says
which participant this is; `capability_id` says what it is one of, so `human/alice` and
`human/bob` — two different participants who both afford only `approve` — share one.

It is derived on demand and never serialized: a second id on the wire would be a second thing
to keep honest. The registry stores it to answer `by_capability_id`.

## Fields

| Field | Answers |
|---|---|
| `handle` | who it is, addressably — `namespace/name` |
| `kind` | `model` `agent` `tool` `service` `human` `robot` `notebook` `pipeline` |
| `display` | name, description, icon, tags |
| `provenance` | vendor, version, licence, source, which adapter produced this |
| `runtime` | residency, host, device, resources, cold start, concurrency, cost |
| `affordances` | what it can do |
| `bindings` | how to reach it — one participant may have several |
| `io_defaults` | media types in and out |
| `artifacts` | what files it can read and write |
| `permissions` | scopes needed and demanded, worst-case side effect, approval policy, egress, filesystem |
| `liveness` | how to check whether it is up |
| `extensions` | namespaced, for anything this vocabulary does not cover |

Deliberately absent: timestamps. "When did we first see this" belongs to the registry, so the
document hashes identically across runs.

## Affordances

```jsonc
{
  "name": "classify",
  "summary": "Label a sentence positive or negative",
  "kind": "invoke",              // invoke | stream | property | event
  "operation": "invoke",         // optional for invoke/stream; required otherwise
  "input_schema":  { /* JSON Schema 2020-12 */ },
  "output_schema": { /* JSON Schema 2020-12 */ },
  "examples": [{ "input": {...}, "output": {...} }],
  "determinism": "deterministic",  // deterministic | stochastic | side_effecting
  "latency_class": "instant",      // instant | seconds | minutes | hours | human
  "idempotent": true,
  "cancellable": true,
  "side_effects": "none",          // none | read | write | external | irreversible
  "scopes": []
}
```

The four kinds come from [W3C WoT](https://www.w3.org/TR/wot-thing-description11/). A
classifier invokes, an LLM streams, a robot joint is a property, a monitor emits events.

Kinds describe the interaction shape; operations decide the authorized path. `invoke` and
`stream` use `invoke` (omitted on legacy descriptors), a property declares `read` or `write`,
and an event declares `subscribe`. A readable and writable property is therefore represented
by two caller-relative affordances. They can carry different input schemas, side effects,
scopes and grants, so permission to observe `light.on` never implies permission to change it.

`latency_class: human` is what lets a person sit in the same participant list as a GPU without
the runtime needing a special case.

`examples` are load-bearing. Automatic capability matching from types alone does not work; a
worked input/output pair is what tells one `classify` from another.

### Artifact-valued arguments

An argument that carries a file is a digest string on the wire, marked with
`x-maiku-artifact` so it can be resolved while ordinary JSON Schema validation still applies:

```jsonc
{ "type": "string", "pattern": "^sha256:[0-9a-f]{64}$",
  "x-maiku-artifact": { "media_type": "image/png" } }
```

## Calls

One call is a stream of events, terminating **exactly once**:

| Event | Meaning |
|---|---|
| `started` | the call began |
| `progress` | still working, optionally with a fraction |
| `delta` | one increment of output (`text`, `data`, `file`, `tensor`) |
| `artifact_written` | a file was produced |
| `needs_input` | suspended, waiting on an answer |
| `needs_approval` | suspended, waiting on permission |
| `log` | diagnostics |
| `usage` | what it consumed, in whatever unit it bills in |
| `finished` | terminal success; `result` is JSON matching `output_schema` |
| `failed` | terminal failure with a code |

The router dispatches `invoke`, `read`, `write` and `subscribe` through the matching adapter
operation after one authorization and validation path. The invariant is enforced centrally
in `guarded()`, not by convention, so a misbehaving third-party adapter still terminates
once. Task states are A2A's verbatim, so the projection is a rename rather than a lossy
mapping.

## Grants

```jsonc
{
  "issuer": "user", "subject": "pipeline",
  "capabilities": [{ "participant": "demo/vision", "affordance": "classify" }],
  "scopes": ["fs:read"],
  "artifacts": ["sha256:..."],
  "max_side_effect": "write",
  "expires_at": 1788200000.0,
  "parent_id": "grant_..."
}
```

One rule: **a derived grant may only narrow** — across capabilities, scopes, artifacts,
side-effect ceiling and expiry. `assert_narrows()` is the whole security model, and
`verify_chain()` checks a delegation chain root-first.

`*` is the wildcard for both capabilities and scopes; a root grant holds both.

## Projections

| Target | Fidelity |
|---|---|
| MCP tools | high — schemas and behavioural hints both survive |
| OpenAI function tools | high for input; no output schema in the format |
| A2A AgentCard | outbound high; **inbound lossy**, because A2A skills carry no schemas |

Inbound A2A gets the message-shaped input schema rather than a fabricated one. Guessing types
nobody stated is how a registry starts lying.
